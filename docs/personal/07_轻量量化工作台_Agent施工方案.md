# 个人量化系统：规划与Agent施工方案

2026-10-18更新｜唯一施工入口。基于TSP有限适配，复用已有界面与研究流程，不再从头建设平台。

当前数据与启动方法见[使用入口](README.md)。**已接通知行策略信号；完整账户回测尚未通过验收，先修执行层，再比较收益。**

## 1. 目标与路线

**先把回测做对，再跑通一条策略，用逐笔复盘和少量因子迭代，最后进入模拟与小规模实盘。**

- 面向个人、几十万至几百万元，日线为主，盘后运行，减少盯盘。目标每天查看约15分钟、每周复盘约1小时，记录实际耗时。
- 初期争取扣费年化20%+；长期再验证百万级资金50%+的可能性。历史最大回撤25%是研究上限，不是实盘风险额度。收益目标不作为调参必须达到的数字。
- 优先在TSP上少量适配：保留页面、图表、策略与因子流程；接本地数据，补正确性和你的复盘功能。Qbot只作参考，QuantDinger暂不引入。
- 研究工作台与生产隔离。新流程验收后替代旧研究和日常入口；旧代码、数据与结果归档保留，不擅自停服务、删除或接管真实账户。

成功标准：同一输入能复现、每笔成交可解释、账本能重建；策略在未用于调整规则的数据上有扣费正期望，回撤可承受，不依赖少数幸运交易。平台交付和策略盈利分别验收。

## 2. 最小系统：一个工作台，三个清楚的环节

```text
本地行情、历史状态、已公告基本面（只读）
  → 召回：知行回调再转强起步，保留候选与路线
  → 排序：独立因子计算，输出分数、排名与贡献
  → 执行：共用现金账户，输出订单、成交、现金与持仓账
  → TSP：实验对比、曲线、逐笔复盘、次日计划、Agent交接
```

因子是独立计算模块，在同一界面里与策略联合测试，不拆成多个服务。Alphalens用于因子诊断，QuantStats用于账户收益报告；两者都不能替代成交账本。

**执行引擎先核对，再确定。** 先修正TSP已复现的同日收盘卖款用于开盘买入问题，用手算样例及现有Backtrader执行层交叉核对。若TSP撮合、公司行动需要大范围重写，就用已核验的Backtrader作为执行后端，TSP展示其封存结果；不同时维护两套权威收益口径。Backtrader也须按本次输入和规则重新验收，不能因已有测试而免检。

保留五个入口：策略实验、结果验收、逐笔复盘、因子研究、每日计划与Agent。优先复用TSP已有页面；缺少功能才扩展。隐藏无关盘中功能，不先物理删源码。首版不做自动下单、复杂机器学习、大规模寻优、多Agent编排或大型产业知识图谱。

## 3. 分步完成，每一步都有可检查的结果

| 步骤 | 做什么 | 完成标准 |
|---|---|---|
| **1 隔离启动** | 固定TSP版本和依赖；独立Python环境、数据目录、端口；保留研究入口 | 桌面与手机宽度能打开；不依赖旧Web或复盘库；无券商连接、无原始数据写入 |
| **2 接本地数据** | Python Provider读本地Parquet；先少量股票、ETF与指数日线，再扩范围 | 日期、量额单位、原始价、复权和缺数行为对拍；缺数明确报错，不静默联网 |
| **3 回测验收** | 修成交时序；核对共用现金、T+1、数量、涨跌停、停牌、费用、公司行动及期末持仓 | 手算、未来隔离、账本重建和重复运行通过；页面与文件一致，才比较历史收益 |
| **4 跑通首条策略** | 冻结知行回调再转强规则与工程基线排序；串起实验、曲线、逐笔、日志和单文件报告 | 同一基线可复现；任一交易能追到规则、因子、成交和现金；做到这里即可日常研究 |
| **5 少量因子迭代** | 相同候选、相同执行规则，对照原排序与单因子，再试少数等权组合；Top1/3/5 | 同时报收益、回撤、盈亏比、胜率与成本；样本外无支持则不加入有效版本 |
| **6 盘后模拟** | 每天封存次日计划，记录模拟成交、拒单与偏差；每周复盘 | 建议至少60个交易日且30笔结束持仓后复核，信号少则延长；这是最低观察门槛，不是盈利证明 |
| **7 小规模实盘与扩展** | 人工明确风险预算后试运行；对比实际与模拟；再增加B2、突破、续接或一个因子 | 执行偏差可解释，有停止与回退规则；扩大资金另评容量，不为收益目标自动加风险 |

阶段1—5可由Agent按授权连续施工，每段交付可用结果；模拟观察不能用历史回放冒充。若阶段3需要持续大改核心，停止扩大TSP定制，比较“现有执行后端接入”与“薄网页展示结果”的改造范围后采用更小方案。

每阶段保留上一个通过版本；数据接入失败撤回Provider，核心修复失败回到固定上游版本，策略改动失败回到上一有效策略。回退不删除失败实验，也不覆盖已封存结果。

## 4. 策略怎么迭代

**一条策略、一项假设、一次对照。**

1. 从下文知行回调再转强v0起步，旧规则只作对照；改变规则须新建实验版本，不覆盖已封存结果。
2. 在看结果前写明：股票池、召回、入场、止损、减仓、退出、仓位、0AMV作用、买入前计划盈亏比与目标来源。不能用未来最高价充当买前目标；跳空后按实际可得价格重算风险，超预算按规则拒单。
3. 先跑原排序；再分别验证行业相对强度、回调量能、已公告现金质量。每轮最多三个简单变体，保留全部尝试。因子分数不是胜率，不预设加因子一定有效。
4. 先看覆盖、Rank IC、分组及候选排序增量，再看共用资金回测。调整买点、卖点、仓位或择时分别做消融，不同时改完后归因给一个因子。
5. 按时间先后做训练/验证/最终留出；持有期标签跨边界的样本隔离，不随机打散日期。已反复查看的历史只能作为回顾研究，不能重新命名为样本外。最后用新增数据继续验证。
6. 产出一张决策卡：问题、改动、数据事实、反例、代价、保留/观察/否定、下一步。通过后形成候选版本，人工review后才切换有效版本。

产业、政策与长期趋势先作为带来源和发布时间的研究卡。缺乏历史可得版本的判断，只用于当前观察，不回填历史。多周期先用日线与已完成周线；0AMV优先作为市场环境/仓位变量，避免与个股评分重复计权。

## 5. 每次review必须能看清什么

| 层次 | 必须展示 |
|---|---|
| **账户** | 扣费累计/年化、基准净值、回撤/恢复、仓位、现金、月收益、费用、拒单、未平仓和数据缺口 |
| **交易** | 完整持仓归并分批成交；进出场K线、白黄线、计划风险/目标、实际成交、退出原因、最大浮盈/浮亏、持有期与R倍数 |
| **分类** | 大赚≥20%；盈利[5%,20%)；接近持平(-5%,5%)；亏损(-10%,-5%]；大亏≤−10%；未平仓单列 |
| **集中度** | 盈利及亏损Top1/5/10贡献；剔除后的表现只作事后压力诊断，不当成可执行策略的新收益 |
| **实现** | 规则版本、原始因子和贡献、信号时间、订单、成交、费用、现金；可遮住未来走势逐笔查看 |
| **结论** | 哪些实际运行、哪些未通过、哪些未知；不显示无法定义的胜率/夏普，标NA并说明原因 |

剔除交易的重算必须预先说明口径：按完整持仓移除对应成交与现金流、保留原资金与日期、重建每日权益，其他交易暂固定；不能简单从年化数字减去盈利。它不模拟空出的资金和名额再投资，另跑策略才能回答可执行性问题。

计划盈亏比、实际平均盈亏比和最终R分别展示；不能只追求胜率，忽略大赢家被提前卖出或亏损尾部变厚。

## 6. 数据、维护与Agent交接

- TSP使用独立环境（所审版本要求Python≥3.11）；已有因子/执行环境按锁定版本隔离，通过文件或子进程连接，不强行统一依赖。
- 原始市场数据只读；TSP派生数据、状态和实验结果分目录。TSP的`ex_factor`是单次事件比值，不能把Tushare累积`adj_factor`直接改名使用。
- 按[00共同接口](00_共同接口与验收.md)交接：`trade_date, ts_code`唯一键；因子与未来标签物理隔离；全部候选、路线、评分和缺失标记保留。历史退市、公告版本不足就披露，不能宣称无幸存者偏差。
- 每次写新运行目录，封存`resolved_spec.json`、`manifest.json`、`validation.json`、signals、orders、fills、cash_ledger、positions_daily、equity_daily、trades、rejections、metrics及`report.html`。结果统一写入`$DATA_DIR/research/<strategy>/<run_id>/`，原始市场数据根目录只读。当前信号回放只输出manifest、候选/预警CSV和report.html；其余账本文件待执行层完成后提供。
- Agent任务只保留五类：新想法、分析选中交易、修改一条规则、比较实验、交接。`task.json`写目标、父版本、可改文件、输入、试验预算和验收；`handoff.md`写结论、未通过项、产物路径、准确命令和下一步。不依赖聊天历史。
- 固定上游commit和实际依赖，定制优先放Provider、因子、策略和扩展目录。核心改动保留最小补丁及回归样例；锁定安装失败即停止，不重新解析依赖后假装同一环境。升级先在副本验证，禁止自动跟随main。
- 研究中Agent可自动计算和整理；切换每日有效版本保留人工review记录。真实下单、扩大资金、外发和生产切换不包含在研究授权内。

## 7. 验收与实盘门槛

**软件先验收：** 手算样例、账本重建、未来数据修改/截断、重复运行、导入幂等、任务失败/中断恢复、页面与文件对账、真实桌面/手机宽度浏览器。费用按声明的舍入规则逐项核对；误差阈值沿用00及02并报告实际值。未通过不标绿，缺浏览器不算页面验收。

**策略再验收：** 尽量覆盖本地可得的约五年及不同市场状态，检查成本压力、参数邻域、分时段结果、50万/100万/300万元的费用与流动性。报告全部尝试、样本量和不确定性。20%目标未达就如实报告，不删除亏损、不提高杠杆补数字。

**实盘另填风险卡：** 可投入且不影响生活的资金、试运行额度、损失触发线、停止条件、复核日期和成交方式。未填写不妨碍开发与模拟，但不得自动实盘或扩仓。首版不融资，历史回撤25%不代替实盘风险预算。

旧任务只在新流程验收、列清备份与恢复命令、取得生产切换授权后停用，避免两套流程同时生成冲突计划。

## 新增对照：知行回调试仓 v0（三日验证）

策略ID：`personal_zhixing_early_v0`。与“知行回调再转强”独立保留，不覆盖原规则。研究目标是胜率接近50%、扣费后的实际平均盈利/平均亏损≥3；目标未验证，不用计划盈亏比冒充已实现盈亏比，也不通过调参硬凑数字。

### 规则清单

- [x] **趋势**：白线高于黄线，黄线不低于5个有效交易日前；沿用知行白黄线公式。
- [x] **回调入场**：当日KDJ(9,3,3)的J≤20，收盘不低于黄线、且不高于白线的102%；不等J拐头、突破前日高点或重新站回白线。
- [x] **量价过滤**：近20日曾出现5日均量≥前5日60日均量的2倍；10日和20日上涨日量均大于下跌日量，涨跌以相邻收盘价比较；60日最高/最低振幅<80%。只作原基线的共同过滤，不增加新评分。
