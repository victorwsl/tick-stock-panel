# 交易回测施工与验收

先阅读同目录 `00_共同接口与验收.md`。请完成实现、运行验收、实际回测和 HTML 复盘报告；不能只停留在技术选型。目标是确保真实共用资金下的订单、仓位、费用和收益都能逐笔核对。

## 1. 选型与边界

基于TSP现有执行路径先做小范围核对和修复；若需大范围重写，再接已有Backtrader作为唯一权威执行后端。选型顺序以[系统方案](07_轻量量化工作台_Agent施工方案.md)为准。QuantStats只负责账本验收后的收益报告，不参与撮合。

优先复用现有仓库、策略、订单与结果接口，不新增第二套账本或通用框架。不修改生产状态，不因为框架能运行就默认A股成交规则正确。

## 2. 输入和预注册实验

直接读取冻结的候选/分数文件和manifest。候选不完整时可以先做引擎样例和基线验收，但正式因子比较必须等待真实交付包，不能用临时自算排名替代。

首轮只验收知行回调再转强与工程基线排序，不同时寻优入场、退出和因子权重。具体规则见系统方案。执行验收通过后，再固定同一候选与交易规则，比较原排序、原尺度等权、同方向横截面归一化等权，各跑Top1/3/5；因子未证明有效就不强行融合。

TopK是每日候选数，不等于最大持仓数。主比较冻结初始资金、最大持仓、仓位、费用、股票池和买卖规则；若研究每只1/K的组合，单独列组，不能混淆选股与分散化贡献。

不可成交时是否递补必须预先固定，默认不越过 TopK 补买；已有策略不同则按冻结策略执行并注明。重复入选已持仓股票是否加仓、信号有效期、卖出资金何时可重用、订单排序均在 spec 中冻结。

先按既有历史窗口回归，再扩展到本地数据支持的连续区间；所有已查看区间标回顾性研究。成本敏感性作为辅助结果，不据此选最佳配置。绝不同时优化入场、退出和因子权重。

## 3. 撮合规则必须可追踪

### 时间与订单

- T 收盘信号只在之后执行；关闭会让当日信号按当日收盘成交的快捷模式。
- 开盘价格可用于开盘成交数量/可成交性，不得读取当天全日高低来决定是否下单、排名和开盘仓位。
- 区分已在前一时点生成的止损订单与盘后才知道的均线破位。后者只能在下一可交易时点卖出。
- 日线同时触及止盈和止损，无法确定路径时采用预先声明的保守顺序，并单列歧义交易；不能事后选有利价格。
- 跳空越过止损价按可执行价格处理，不能保证在止损阈值成交。涨跌停队列、停牌及成交量限制须明确建模。

### A 股约束

- 按交易日期、板块、ST/上市阶段使用对应涨跌停和下单数量规则，不能全市场永久固定 10% 或一个手数规则。
- 股票当日买入不能当日卖出；分批买入时按可卖数量核算。已有持仓的可卖部分不应一起锁死。
- 停牌无成交；缺行情与停牌分开处理。无可靠行情时不能填零价、跨越数据缺口假造成交。
- 佣金、最低佣金、卖出印花税、过户费按预先声明的账户假设和历史生效区间计算；滑点独立列出，数量和资金不足要拒单或减量。
- 除权、分红、送转处理现金/应收、股数、成本和估值，不能既用复权价又发一次股息。到账日期和除权日期区别明确。
- 未平仓期末继续估值并列未实现盈亏；如展示强制平仓情景，独立标记且遵守可成交条件。

### 账户守恒

所有股票共享一个真实现金账户，不能把每只股票独立满仓收益相加。每个事件后检查：

`净资产 = 可用/冻结现金 + 持仓市值 + 应收权益 − 应付款项`

无融资模式现金和可卖股数不得为负。资金冻结、买卖、费用、分红和到账均有账本记录。重复候选、重复事件或重跑不能造成重复成交。每日收益来自账户净资产变化并正确处理外部资金流；无资金流时为 NAV_t/NAV_(t−1)−1。

## 4. 必过验收：先手算，再真实股票

| 场景 | 必须检查 |
|---|---|
| 100→110→99→105 的账户净值 | 含初始点，最大回撤 10%，与 QuantStats 对齐 |
| 前日收盘信号，次日跳空 | 使用次日可成交价格，信号和买入日期明确分开 |
| 一笔买入、一笔卖出，含最低佣金与税 | 逐笔数量、现金、成本、盈亏与手算一致 |
| Top3 同时买入、现金只够部分 | 固定订单优先级，不透支，不各自独立满仓 |
| 当日新买与历史持仓混合 | T+1 可卖数量准确 |
| 涨停买不到、跌停卖不出、连续停牌 | 订单状态、有效期、持仓估值与后续处理准确 |
| 止损日跳空、同日止盈止损 | 无理想止损成交，无有利路径挑选 |
| 分红送转、退市/末日无行情 | 权益无重复计入；无自动消失的亏损持仓 |
| 修改未来行情并截断数据重跑 | 截断日前决策和成交不变；不使用全日成交量影响当日开盘决策 |
| 股票数据顺序打乱、事件重复输入 | 排序确定、主键校验、输出不重复 |

统计容差 1e-10；现金按账本声明的最小货币单位核对。独立预期值不能调用被测引擎的同一个函数生成。测试失败必须修复后再跑全量，禁止靠删掉困难交易通过。

## 5. 与旧引擎对账

同一小窗口、同输入、同参数逐事件比较：选股→订单→成交→持仓→现金→净值。按最早分歧定位，输出 `engine_diff.csv`，解释每个非零差异。旧引擎有错误时保留旧基线，记录修复前后，不以贴近旧收益为目标。

再选本地真实数据中包含停牌、涨跌停、除权的短窗口对照行情人工复核。若本地缺某事件，合成样例仍必须通过，真实验证缺口明确列出。

## 6. 输出文件与复盘报告

输出 `$DATA_DIR/research/<strategy>/<run_id>/`，不写入原始市场数据根目录：

- `resolved_spec.json`、`manifest.json`、测试与对账日志；
- `signals.parquet`、`orders.parquet`、`fills.parquet`、`cash_ledger.parquet`、`positions_daily.parquet`、`equity_daily.parquet`；
- `trades.csv`、`rejections.csv`、`engine_diff.csv`、`metrics.csv`；
- 自包含单文件 HTML，手机可读、可下载明细。

交易复盘表至少包含：股票、路线、信号日期、原/新分数及贡献、入选排名、计划/实际买卖时点、数量、成交价、费用、持有期、退出原因、净盈亏、MAE/MFE、买卖失败原因、期末状态。分批买卖与汇总交易有明确 ID 对应，盈利亏损表覆盖全体，不只展示好看的样例。

图表：账户净值与同期间基准、回撤曲线、仓位/现金曲线、月收益热力图、逐年结果。指标：总收益、按真实跨度年化收益、最大回撤及恢复时间、波动/夏普/Calmar、胜率、盈亏比、profit factor、交易数量、换手、费用占比、资金利用率、未实现盈亏、拒单比例。无亏损、短样本等导致比率不可定义时显示 NA，不能显示夸张的无限值当成优秀结果。

QuantStats 只接收经过账本验收的逐日收益与本地基准。固定无风险收益率、年化频率、基准起点；基准缺失不能填零。报告区分已平仓统计与账户总体表现。

## 7. 完成标准和结论

只有验收样例全部通过、账户逐日守恒、真实短窗复核完成、主矩阵实际运行并保存可复现产物后，才能说“回测实现已通过本次验收”。数据不足或接口未交付的配置列未运行及原因，不按完成计算。

结论分别回答：实现是否正确；因子是否改善原系统；改善来自选股还是仓位/风险暴露；哪些亏损是策略本身、哪些是成交限制、哪些是数据不足。不能以历史最大回撤低于 10% 宣称未来损失上限 10%。交付报告不等于授权上线。
