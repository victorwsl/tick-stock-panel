## 配置与启动

在fork根目录创建本机`.env`，不提交凭证：

```dotenv
HOST=127.0.0.1
PORT=8603
DATA_DIR=./data/personal_trial
PERSONAL_LOCAL_ONLY=true
SLQUANT_DATA_ROOT=<已有行情根目录>
```

在设置中将日K、复权因子和财务数据源选为`local_parquet`，关闭实时行情及矩阵自动预热。日常页面只读本地，不自动在线回退；本地模式不是操作系统网络沙箱。没有券商连接、自动下单、外部通知或自动AI任务。

```bash
# 重建锁定环境（首次）
cd backend
uv sync --frozen --extra dev --extra backtest --python 3.12
cd ../frontend
pnpm install --frozen-lockfile
pnpm build
cd ..

# 安装策略；重复执行不覆盖手工修改
backend/.venv/bin/python scripts/personal_trial.py install-strategy
# 使用已有派生库启动，Ctrl+C停止
backend/.venv/bin/python scripts/personal_trial.py serve
```

地址为 http://127.0.0.1:8603，仅运行服务的电脑可直接访问；其他设备的127.0.0.1指向其自身。端口占用会退出，不杀其他进程，不用会抢占端口的原dev.sh。

## 回测历史

策略回测完成后，完整配置、净值、回撤和逐笔交易自动保存到`DATA_DIR/backtest_history/<id>/`。回测页顶部可选择历史记录；重新进入时默认恢复最新一份。修改策略或左侧参数不会改写历史结果，原始运行配置可展开查看。历史文件包含全部交易，备份数据目录时一并保留。

结果与摘要一起原子写入，保存失败在页面明确提示。失败或取消的任务不当作成功历史；五分钟内存缓存仅用于任务重连，不再承担持久保存。旧版只存在浏览器或已过期缓存中的结果不能保证恢复；浏览器尚存的末次结果仍可显示，但不等于已写入磁盘。历史回放的K线仍读取当前本地行情，尚未冻结行情快照，数据修订可能影响回放；原始收益和成交记录保持保存时的值。

## 因子筛选历史

因子页“批量筛选”完成后，结果和原始参数自动保存到`DATA_DIR/factor_research/backtest_history/<id>/`。结果区域上方的“因子筛选历史”可切换记录；刷新或重新进入页面会恢复最近一份，不重新计算。左侧参数用于下一次运行，原始参数在当前结果下展开查看。保存失败会明确提示，当前结果仍可查看；更新前只存在页面内存中的结果无法恢复，需要重跑。此入口保存批量结果表，单因子详情仍是单独运行。

## 中低频因子研究选项

批量筛选与单因子检验可独立设置未来20／60／250交易日预测和日／周／月调仓，默认60日预测、月度调仓、最近5年请求区间。快速筛选按钮按期限设置3／5／8年，仔细验证设置10／12／15年；按钮只设置历史跨度，不会补数据或自动完成样本外验证。实际行情范围、成熟样本、有效IC日期和不重叠区间随结果显示，不能用请求年份冒充已有历史。

预测标签为T日收盘特征对应T+1市场交易日开盘至T+H收盘；缺入口或到期价格保留缺失，未成熟标签排除，年度按250交易日直接计算。IC每天计算，HAC滞后为`max(1,H−1)`，缺HAC结果不退回普通t检验；少于8个不重叠区间仅作探索，8是本项目初筛门槛，并非统计有效的充分条件。分组预测收益为先每日等权再对日期平均的毛收益，不将重叠H日收益连乘。

分层净值、多空收益和回撤仍是原有按调仓频率计算的收盘理论组合；调仓间隔内的回撤未计入，不能当作账户回测。结果保存原始预测期限，旧记录标注“旧版随调仓变化”。技术行情已扩展到2005年以来；长期尤其年度因子仍需保留独立时间段验证，财报与其他外部因子按各自真实覆盖范围处理。

## 本仓库Tushare采集与持久化（2026-10-19）

访问、凭证、限频和有限重试已从TradingSimple迁入`backend/app/services/personal_tushare.py`，不需要另一份仓库或Tushare SDK。读取`TUSHARE_TOKEN`/`tushare_token`或`TUSHARE_TOKEN_FILE`；已有配置可通过`--env-file`读取，只接收Tushare配置项。不会写`~/tk.csv`、复制Token或修改shell。沿用旧仓库当前默认`https://fast.xiaodefa.cn`，可用`TUSHARE_API_URL`/`tushare_api_url`显式切换已核对的官方地址或`https://tt.xiaodefa.cn`；保持TLS验证，不跟随跳转、不使用代理环境。

通用补数命令先查本地的同一请求块，缺失才联网；结果按资产、接口和请求指纹写入Parquet及`receipt.json`。请求指纹包含数据源、参数和字段，Token不参与。重复执行可直接读本地，不需要Token；文件损坏拒绝覆盖。数据源、字段或日期区间变化属于新请求，**没有实现任意重叠区间的逐行缺口合并**。不同股票、ETF、指数、日历和财务分别存放。

例如获取一只ETF五天原始日线：

```bash
backend/.venv/bin/python scripts/fetch_tushare_data.py \
  --cache-dir data/tushare_cache --asset etf --api fund_daily \
  --params '{"ts_code":"510050.SH","start_date":"20261012","end_date":"20261016"}' \
  --fields ts_code,trade_date,open,high,low,close,pre_close,vol,amount
```

输出JSON给出实际Parquet路径、行数和`cache_hit`；再执行同一命令应为`true`。原始价格、量额单位保持供应商口径，不把缓存直接当成已校验行情。空响应退出2并标`empty_unverified`；权限/网络/字段/日期/重复键/截断门槛错误退出1，不生成成功清单。达到单次行数门槛须缩小范围；通用命令不会假装已完成分页。需要有系统缺口审计、自动分段及中断续传的ETF研究使用`audit_etf_data.py`→`fetch_etf_data.py`，继续保留C07/C08门槛。原在用缓存、规范行情和历史回测不由通用命令覆盖。

财务采集入口也已改为本仓库客户端，保留逐季度缓存、财务版本与冲突隔离。旧`--collector-root`参数仅为旧命令兼容保留，不读取该路径：

```bash
backend/.venv/bin/python scripts/fetch_size_financials.py \
  --output data/tushare_financials/<新编号> --start 20260331 --end 20260630
backend/.venv/bin/python scripts/fetch_value_momentum.py \
  --output data/tushare_value_momentum/<新编号>
```

财务脚本仍按原研究字段及范围工作；它们不是全市场所有数据的一键迁移器。季度分页有次数上限及重复页保护，限频/超时仅有限重试，权限不足不反复请求。已封存结果拒绝覆盖。股票和ETF旧显式sync入口共用新连接模块，原导入规则与已有缓存路径保留；长历史股票不能用短窗口sync覆盖，仍遵守上文限制。

**使用顺序是补数落盘→核验与规范化→导入/发布版本→本地研究。** Web、因子、策略和回测不隐式联网补数；这一轮没有重启Web、自动导入或发布ETF数据。实际第三方请求被自动审批拦截，需明确授权向`https://fast.xiaodefa.cn`发送现有Token后再做真实下载验收；不需要在聊天中提供Token。
